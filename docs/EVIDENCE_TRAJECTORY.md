# Evidence register — body trajectory model

To be merged into docs/EVIDENCE.md when bodyTrajectory is wired (v0.7).

This register covers `src/astro_brain/trajectory.py` only. Every magnitude
(rate, plateau value, breakpoint-day anchor value) traces to a row of
`docs/BODY_TRAJECTORY_RESEARCH.md` §1 — the only numeric source for this
module — and keeps that row's VERIFIED/VERIFY status unchanged. Curve
shapes, breakpoint *days* not stated by the research doc, the
adherence-interpolation model, and the uncertainty band are prototype
**DESIGN DECISION**s with no cited numeric source, listed separately below.

## DESIGN DECISION rows

| decision | rationale | where it lives in code |
|---|---|---|
| Adherence linearly interpolates between the no-countermeasure and with-countermeasure rate | The research doc verifies only two discrete points (no countermeasure vs. ARED/SPRINT-era countermeasure) for the two bone parameters; no cited source gives a continuous adherence→outcome function. A continuous multiplier between the two endpoints is this module's own choice, applied only where both rates exist. | `_interpolated_rate()` in `trajectory.py` |
| Adherence is ignored (no effect on `expected`) for every parameter except the two bone ones | The doc gives a numeric with/without-countermeasure split *only* for bone (row 1b). Every other parameter's countermeasure discussion is qualitative (ARED-era muscle, SPRINT, higher-intensity aerobic exercise, Skylab caloric adequacy, compression garments, LBNP candidates) with no % to interpolate against. Forcing a number here would violate "never add a number the doc does not contain." | `TrajectoryParameter.has_countermeasure_variant`; `rate_with_countermeasure_pct_per_month is None` branch of `_interpolated_rate()` |
| `exercise_adherence` represents *exercise* countermeasure adherence only, never dietary/caloric adherence | The input contract (`mission_day`, `exercise_minutes_today`, `required_exercise_minutes`) only exposes an exercise-adherence axis. `body_mass_pct`'s documented countermeasure (adequate caloric intake, Skylab) is dietary, not exercise, so it is deliberately left unmodeled rather than overloading the one adherence parameter to mean two different things. | `body_mass_pct` entry (no `rate_with_countermeasure_pct_per_month`) |
| Two curve shapes: `"linear_per_month"` and `"early_drop_then_plateau"` | Collapses the research doc's four named shapes in its own §3 sketch (`linear_with_countermeasure_damping`, `exponential_approach_to_asymptote`, `piecewise_linear`, `step_at_landing_then_decay`, `step_onset_within_first_month_then_flat`) into two mechanically equivalent cases: a constant monthly rate, or a piecewise-linear curve through named anchors held flat after the last one. The underlying magnitudes are unchanged; only the curve-fitting mechanism is simplified for a <400-line, stdlib-only module. | `CURVE_LINEAR_PER_MONTH`, `CURVE_EARLY_DROP_THEN_PLATEAU`, `_piecewise_value()` |
| Breakpoint *days* not stated by the doc (muscle plateau at day 180, body mass plateau at day 30, orthostatic ramp to day 120) | The doc gives the end-state magnitude but no explicit day for when it is reached, for these three parameters specifically (contrast with VO2peak's day 14 and SANS's day 30, both directly quoted). Chosen for internal consistency with the doc's own "4–6 month" long-duration framing (muscle, orthostatic) or as an early-adaptation-window default (body mass). | `TRAJECTORY_PARAMETERS` breakpoints tuples |
| `MISSION_LENGTH_TYPICAL_DAYS = 180` and the `extrapolated` flag | The doc repeatedly frames long-duration missions as "4 to 6 months" (rows 1a, 5); 180 days (6 months) is used as the boundary past which this model's curves are extrapolated beyond their documented range, per the task's guard-rail requirement. | `MISSION_LENGTH_TYPICAL_DAYS`; `extrapolated = mission_day > MISSION_LENGTH_TYPICAL_DAYS` in `expected_change()` |
| `lower`/`upper` = `expected` ± 25% | No row in the research doc states a confidence interval; two rows state a standard deviation (bone, row 1b), which is a different statistic from a CI and is not reused as one. A flat ±25% band is applied to every point as a visibly-labelled placeholder uncertainty range. | `UNCERTAINTY_BAND_FRACTION`; `_uncertainty_band()` |
| `DAYS_PER_MONTH = 30` | Matches the %/month unit the research doc itself uses for the bone rates (row 1b); a calendar-month approximation, not a cited conversion factor. | `DAYS_PER_MONTH` |
| Generic physiologic clamp: percent-change parameters bounded to [−100, 100], probability parameters bounded to [0, 1] | The doc states no floor/ceiling for any parameter (bone's `floor_pct` is explicitly `None — NOT FOUND` in its own §3 sketch). These are generic sanity bounds (cannot lose/gain more than 100% of a quantity; a probability cannot leave [0, 1]), not doc-sourced clinical limits. | `_clamp_to_physiologic_range()` |
| Population expectation, never a measurement or diagnosis | Required framing from `docs/BODY_TRAJECTORY_RESEARCH.md` §4 ("What must be labelled on the UI") and `AGENTS.md`'s `likelyConditions` precedent. Every output carries this disclaimer verbatim. | `DISCLAIMER` constant; `to_dict()["disclaimer"]` |

## What is intentionally out of scope

- SANS persistence beyond onset (20+ month outlier cases) — onset risk only, per row 6's VERIFY-free onset numbers; persistence has no single number to plot.
- Post-landing decay/recovery legs for `vo2peak_pct` (day 180→210) and `orthostatic_intolerance_risk` (landing day→R+3) — out of the `mission_day` (in-mission) domain this module operates in.
- Radiation cumulative dose (row 7) — already covered by the existing `RADIATION_30DAY_LIMIT`/`RADIATION_CAREER_LIMIT` flags and `docs/EVIDENCE.md`; row 7 itself says "cross-referenced here, not re-fetched," and this module does not duplicate it.
- Any wiring into `pipeline.py`, `dashboard.py`, or the output contract — out of scope for this change (v0.7a); see `AGENTS.md` for the contract this module will need to join at v0.7.
