# AstroCare

A fully local, offline early-warning system for astronaut health. It takes one vitals/lifestyle
sample at a time, scores it against clinical and operational thresholds, and attaches a short,
plain-language recommendation generated by a local LLM (with a deterministic rule-based fallback
when the model is unavailable or too slow).

Brain module (Scoring Engine + Doctor Layer) of the AstroCare system — NASA Space Apps 2026.

## Architecture

```
            input JSON (vitals + lifestyle sample)
                        |
                        v
             contract validation (contract.py)
                        |
                        v
                 Scoring Engine
        +-------------------------------+
        |  NEWS2  |  radiation | lifestyle |
        +-------------------------------+
                        |
                        v
              IMM-lite (conditions.py)
        ranked condition candidates from flags
                        |
                        v
                  Doctor Layer
        +-------------------------------+
        | cache -> Ollama (3s timeout)  |
        |        -> rule-based fallback |
        |   (background upgrade fills   |
        |    the cache for next time)   |
        +-------------------------------+
                        |
                        v
            output JSON (score, flags, alertLevel,
                         doctorRecommendation)
                        |
                        v
                 UI (other repository)
```

The data pipeline (sensors/simulator producing input JSON) and the presentation UI are owned by
separate repositories/teams; this repository only implements the brain in the middle.

## Why AstroCare

- Fully local, offline AI — Ollama `qwen2.5:7b-instruct`, 3 s timeout, rule-based fallback, background cache warm-up: `doctor/`.
- ExMC-aligned IMM-lite condition ranking using the EMCL/IMM vocabulary — the real-time counterpart to ExMC IMPACT mission planning; not the IMM Monte Carlo, never a diagnosis: `conditions.py`.
- Evidence register: every threshold mapped to a source with VERIFIED/VERIFY/ASSUMPTION/DESIGN DECISION status: [docs/EVIDENCE.md](docs/EVIDENCE.md).
- Graceful degradation: model slow or down → complete, safe recommendation; `doctorSource` shown honestly: `doctor/layer.py`.
- Contract-driven parallel teamwork: [AGENTS.md](AGENTS.md) is the only integration document; 435 tests, mock-data QA.

Details and the honest limitations of each claim: [docs/WHY_ASTROCARE.md](docs/WHY_ASTROCARE.md).

### Doctor Layer: with or without the local LLM

The Doctor Layer talks to a local [Ollama](https://ollama.com) server running
`qwen2.5:7b-instruct`:

```bash
# install Ollama, then:
ollama pull qwen2.5:7b-instruct
```

To run without the model (rule-based text only, no network calls), either pass `--offline` to the
dashboard or set `ASTRO_DOCTOR_OFFLINE=1` for any entry point that builds a default `Brain()`:

```bash
.venv/bin/python -m astro_brain.dashboard --simulate --offline
# or
ASTRO_DOCTOR_OFFLINE=1 .venv/bin/python -m astro_brain.qa
```

Other environment variables read by the default `Brain()` (see `pipeline.py`):

| variable | meaning | default |
|---|---|---|
| `ASTRO_OLLAMA_URL` | base URL of the Ollama server | `http://localhost:11434` |
| `ASTRO_OLLAMA_MODEL` | model name to request | `qwen2.5:7b-instruct` |
| `ASTRO_DOCTOR_OFFLINE` | `"1"` disables the Doctor Layer entirely | unset |

## Scoring rules

| rule | trigger | severity |
|---|---|---|
| NEWS2 (RCP 2017 standard bands, SpO2 scale 1) | per-component score ≥ 2 flags that component; total 5–6 is medium, total ≥ 7 is high | yellow / **red** at total ≥ 7 |
| Radiation | dose rate ≥ 100 µSv/h **or** NOAA S-scale ≥ 2 (elevated); ≥ 1000 µSv/h **or** S-scale ≥ 3 (critical) | yellow / **red** |
| Exercise | `exercise_minutes_today` < 50% of `required_exercise_minutes` | yellow |
| Calories | `caloric_intake` < 70% of `caloric_target` | yellow |
| Sleep | `sleep_hours` < 6 | yellow |
| Mood | `mood_score` ≤ 4 | yellow |
| IMM-lite conditions | deterministic evidence score over the active flags; emit top 3 at confidence ≥ 0.25 | informational (never a diagnosis) |

`alertLevel` is the worst severity among active flags (no flags → `green`). Only `NEWS2_HIGH`,
`RADIATION_CRITICAL`, and the two cumulative radiation limits at 100% can turn a sample red. See
AGENTS.md section 3 for the full flag-code table.

## IMM-lite condition ranking

The brain reuses the ExMC Exploration Medical Condition List (EMCL, JSC-65722) and Integrated
Medical Model (IMM) **condition vocabulary**, but replaces IMM's Monte Carlo mission simulation
with a transparent, deterministic score over the flags it already computed: each condition has
weighted flag drivers, `confidence = min(1, Σ weights / saturation)`, at most three candidates are
returned, and `drivers` shows exactly which flags contributed. This is differential support
("conditions to watch"), not the IMM, not a calibrated probability, and never a diagnosis.
Sources and limitations: [docs/EVIDENCE.md](docs/EVIDENCE.md).

## Doctor Layer

- A known-nominal sample (green, no active flags) and a disabled layer both return the rule-based
  fallback text directly — no LLM call is made.
- An identical `(alertLevel, flag codes)` combination seen before returns the cached text,
  source `"cache"` — this is the debounce: the same flag set never re-queries the model while
  cached.
- On a cache miss, one synchronous call is made to Ollama with a 3 second timeout. On
  CPU-only hardware the 7B model does not answer within 3 seconds, so this call almost always
  times out and the fallback text is returned, source `"fallback"`.
- That timeout hands the cache key to exactly one background thread per key, which retries with a
  longer timeout; on success it fills the cache (~15–25 s later on CPU) so the *next* occurrence
  of the same flag combination returns the model's own text, source `"llm"`, straight from cache
  as `"cache"`. While a key is in flight, further misses on it return fallback immediately without
  starting a second call.
- `doctorSource` tells the caller where the text came from: `"llm"` (fresh model call that
  answered in time), `"cache"` (previously computed, model or fallback), or `"fallback"`
  (rule-based template, no model involved).

## Project layout

```
src/astro_brain/
  contract.py        input contract: typed sample model and strict validation
  flags.py            clinical flags and alert-level aggregation
  news2.py            standard NEWS2 (RCP, SpO2 scale 1)
  radiation.py        radiation flags (dose rate + NOAA S-scale)
  lifestyle.py        lifestyle/operational flags: exercise, calories, sleep, mood
  vitals_flags.py     per-component and aggregate NEWS2 flags
  scoring.py          top-level pure scoring entry point (assess)
  conditions.py       IMM-lite: rank EMCL/IMM condition candidates from active flags
  pipeline.py         Brain: wires contract validation, scoring and the Doctor Layer
  mock.py             mock vitals data matching the input contract
  qa.py               offline end-to-end QA runner over mock scenarios
  dashboard.py        throwaway debug dashboard (http.server, plain-text/JSON)
  doctor/
    layer.py          DoctorLayer: cache/debounce/timeout/fallback/upgrade logic
    fallback.py       deterministic rule-based recommendation text
    ollama_client.py  thin stdlib HTTP client for a local Ollama server
    prompts.py        prompt text for the Ollama-backed recommendation
tests/                pytest suite (one test module per source module)
examples/             sample input/output JSON for manual testing and docs
```

## Medical disclaimer

This is a hackathon prototype, not a medical device. NEWS2 is a terrestrial hospital early-warning
score adapted here for convenience; it has not been validated for spaceflight physiology. NEWS2 was
developed for adult NHS patients, and no validation for astronauts or microgravity was found. SpO2,
blood pressure, temperature, and consciousness may be confounded by spaceflight adaptation; outputs
must not be used as a validated clinical instrument or for real medical decisions.
